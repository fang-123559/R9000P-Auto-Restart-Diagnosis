## 根因分析

### 事件 ID 142 的含义

```
Event ID 142 (Critical) — Microsoft-Windows-Kernel-Power
"系统已重新启动而未先干净关闭。导致此错误的原因是系统已停止响应，
 硬件监视器触发了系统重置。"
```

这是**最高级别的硬件级重置信号**，意味着：
- 系统已经完全冻住（连蓝屏都来不及生成）
- 主板上的硬件看门狗（Hardware Watchdog Timer）检测到系统无响应
- 看门狗超时后强制断电重启

### 可能性排序

| 可能原因 | 证据 | 概率 |
|----------|------|------|
| **AMD CPU 电源管理策略 BUG** | 社区大量同款案例 + 低负载时发生 + 电池计数变化 | **60%** |
| **BIOS 固件 C-State 控制异常** | 5800H 深度 C-State 唤醒失败 | **25%** |
| **电源适配器瞬时供电异常** | 电池计数每次变化 | **5%** |
| **CPU 虚焊（早期阶段）** | 拯救者通病但本机症状不符 | **5%** |
| **Intel WLAN 驱动冲突** | 已更新驱动修复 | **5%**（已排除） |

### 为什么最小处理器状态 100% 没有解决问题？

**关键发现**：即使设置了 OS 层面的最小处理器状态 100%，AMD CPU 的深度 C-State（C6/C7/C8）仍由 **BIOS 固件和 AMD PSP（Platform Security Processor）** 管理，Windows 电源策略管不到这个层面。

```
控制层级：
├── Windows 电源策略（已设置100%） ← 只控制 OS 层
├── AMD PSP 固件（版本 5.18.0.0） ← 控制深层 C-State
└── BIOS 固件（GKCN65WW） ← 最终仲裁
```

|------|------|

```
AMD Processor Power Mgmt: 无版本 → 8.0.1.13

下载链接：
https://drivers.amd.com/drivers/amd_chipset_software_8.05.04.516.exe

官方发布说明：

```

### 方案 C：UMAF 解锁 BIOS 隐藏选项 🔧

通过 UMAF（Universal AMD Form Browser）工具访问联想 BIOS 中隐藏的 AMD CBS 菜单：

```
操作：
1. 下载 UMAF 工具（GitHub: JamesCJ60/Universal-x86-Unlocking-Tool）
2. 制作 UEFI 启动 U 盘
3. 重启进入 UMAF
4. 导航至 AMD CBS → SMU Configuration
5. 设置：
   - C-State Control → Disabled
   - CPPC → Disabled  
   - Global C-State Control → Disabled
6. 保存并退出
```

### 控制策略缺陷

当前系统的控制策略存在**开环盲区**：
- OS 层（Windows 电源策略）可以设置最小处理器状态 100%
- 但固件层（PSP/BIOS）的 C-State 控制**不受 OS 指令约束**
- 导致在 OS 以为 CPU 处于全速状态时，固件已经让 CPU 进入了深度睡眠

解决方案的目标是**打通这个控制链路**：
- 方案B（更新PSP驱动）：修复固件层的 BUG
- 方案C（UMAF）：直接禁用固件层的 C-State 控制
